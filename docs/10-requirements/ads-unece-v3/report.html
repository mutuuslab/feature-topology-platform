P-1플랫폼은 승인된 정책과 증거를 관리하고, 실행 가능성은 차량이 현재 상태로 판단한다. 클라우드는 액추에이터를 직접 제어하지 않는다.화면·API 어디에서도 '정책 ON = 동작 중'으로 읽히게 쓰지 않는다. 플랫폼이 내는 것은 '의도'와 '근거'이고, 차량이 보고한 것은 '실제'로 따로 둔다.
P-2정책 ON ≠ Active · 종료 요청 ≠ 안전 전환 완료 · Rollback 성공 ≠ 재활성화 허가상태를 하나의 ON/OFF 숫자로 합치지 않는다. 의도·전달(수신·수락·보류·실행)·실제(Available·Active·전환 중·MRC·비활성)·최신성(마지막 관측 시각)을 나란히 보인다.
P-3신규 활성화의 보수적 거부와 이미 Active인 차량의 안전 반응은 다른 정책이다. Boolean OFF로 DDT를 끊지 않는다.만료·회수·연결 상실은 '다음 활성화 제한 + 승인된 종료 절차'로만 표현한다(지금의 DC3 체험 만료 처리와 같은 방향).
P-4UNKNOWN은 IN이 아니다. 근거가 없거나 오래되면 허용하지 않는다.ODD·입력 품질·데이터 신선도가 불확실하면 판정 불가로 따로 보이고 정상으로 집계하지 않는다(텔레메트리 Closed loop의 '판단 불가'와 같은 규칙).
P-5주장 → 논거 → 증거에 고유 ID를 붙이고, 증거는 정확한 형상(정책·ODD·HW/SW·모델·보정·도구)에 묶는다.Evidence manifest를 엔티티로 만들고, 다른 형상에서 나온 통과 결과를 재사용하지 않는다.
P-6운영 로그는 DSSAD·법정 사건 보고가 아니다.플랫폼 기록은 '운영 감사 기록'으로 표기하고, DSSAD는 차량 기록으로 링크·상관 ID만 둔다. 법정 보고는 인지 시각·기한을 따로 관리한다.
P-7같은 단어 "적격"이 두 층이다 — 플랫폼의 VIN 적격(구성·권리·시장)과 차량의 활성 적격(ODD·고장·신호). (Orca R3)6축 표마다 판단 주체를 적고, 활성 적격·실제 실행은 차량 보고값만 쓴다. 보고가 오래되면 "확인 불가".
P-8가상 시연을 양산 구현·안전 인증처럼 표시하지 않는다. 실측 전 수치를 성과로 표시하지 않는다. (Orca R3 표현 경계)시뮬레이션·5년 재생 화면에 "가상 데이터·목표 설계" 표기, 사례별 금지 표현을 lint-copy 규칙으로.

상세 시나리오 10 — 지금 → 목표

01 · 구매는 완료됐지만 ODD 밖인 경우

상황 사용자가 고속도로 ADS 상품을 구매했지만 현재 차량은 도심 이면도로에 있다.

보고서의 처리 상품 권한은 유효로 표시하고 차량 활성화는 거부한다. 고속도로 진입 후에도 센서·고장·적용 구성과 필요한 사용자 절차를 확인한다.

보여 줄 결과 “구매됨 / 현재 운행 조건에서 사용 불가”.

지금 플랫폼 평가기는 사용 권한(ENTITLEMENT)과 지원 조건·적용 범위를 따로 판정해 NO_ENTITLEMENT·NOT_SUPPORTED로 나눈다(contracts/src/flags/evaluate.ts:128).

차이 현재 위치·도로 유형에 따른 ODD 판정이 없어 '구매됨 / 현재 운행 조건에서 사용 불가'를 판정하지도 표시하지도 못한다.

반영 ADS-UI06 · ADS-SIM01

02 · 고속 주행 중 결함으로 원격 종료

상황 ADS가 DDT를 수행하는 동안 해당 구성에서 안전 결함이 확인돼 종료 요청이 도착한다.

보고서의 처리 차량은 요청을 검증하고, 종료 후 재활성화 차단을 유지하면서 현재 상태에 맞는 fallback을 수행한다. 사용자 인계가 가능한 기능은 해당 인계 조건을 따르고, 인계 불가·실패 시 적용되는 MRC 경로를 따른다.

보여 줄 결과 수신·fallback 진행·실제 종료를 구분.

지금 플랫폼 Kill v2 DC2 차단은 경고·인계 → 램프 → DISABLED 단계를 밟고 수락·완료 시각을 명령 ID와 기록한다(vehicle-runtime.service.ts:248, kill-timeline.ts:64).

차이 인계 불가·실패 시의 MRC 경로와 DMS 조건을 모델링하지 않아 MRC 시각이 항상 비어 있고, 제어 책임 주체가 기록되지 않는다.

반영 ADS-UI02 · ADS-SIM03

03 · 국가 타기팅 오류를 정책 롤백

상황 허용되지 않은 시장의 일부 차량에 ADS 활성화 정책이 전달됐다.

보고서의 처리 신규 대상 확대를 중단하고 잘못 포함된 차량을 식별한다. 비활성 차량은 새 활성화를 막고, 이미 active인 차량은 안전 종료 경로를 따른다. 단순히 과거 정책을 복원하는 것 외에 이미 발생한 운행·사건을 평가한다.

보여 줄 결과 대상 구성별 미수신·차단·종료 현황.

지금 플랫폼 미확인 시장에서 F2+ 활성화를 막고(FFG-GEN-003) 정책 롤백은 flag 단위 범위·승인으로 처리한다(compliance-profile.ts:59).

차이 잘못 포함된 차량을 식별하고 그 차량의 실제 Active·운행 이력과 시정 결과를 평가하는 흐름이 없다.

반영 ADS-UI01 · ADS-BE05 · ADS-BE13

04 · OTA 설치 도중 전원 차단

상황 업데이트 적용 중 전원이 끊겨 설치가 완료되지 않았다.

보여 줄 결과 설치 실패 / 복구 완료 또는 안전 상태·정비 필요.

보고서의 처리 파일 교체 성공과 ADS 복구 성공을 구분한다. 검증된 조합에 없으면 ADS 활성화를 차단하고 호환 구성을 복구하거나 안전한 수정 버전을 적용한다.

지금 플랫폼 구성 증명(정책 해시 대조)과 다중 ECU 회신 DIVERGED/PARTIAL 판정이 있다(attestation.ts).

차이 모델·런타임·센서 보정·정책의 검증된 호환 집합이 없어 파일 교체 성공과 ADS 복구 성공을 구분하지 못한다.
