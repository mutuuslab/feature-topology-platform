# 20-93 지원 브라우저·해상도 (출시 준비 RD-P2-03)

> 2026-10-25. 시험: `FF/e2e/tests/browsers.spec.ts`(엔진 스모크), `FF/e2e/tests/narrow.spec.ts`(좁은 폭), 설정 `FF/e2e/playwright.config.ts`.

## 1. 지원 범위

| 구분 | 지원 | 근거 시험 |
|---|---|---|
| 데스크톱 브라우저 | Chrome·Edge(Chromium 엔진) 최신, Firefox 최신, Safari(WebKit) 최신 | chromium 전체 e2e · firefox·webkit 핵심 흐름 스모크 |
| 지원 해상도 — 데스크톱 | 폭 1280 이상(설계 기준 1366·1920) | 기존 e2e 전체(1366 기준), 레이아웃 시험(1366·1920) |
| 지원 해상도 — 태블릿 | 폭 768 이상: 보기와 조작(승인·차단 요청 포함) | `narrow.spec` tablet(768×1024) |
| 지원 해상도 — 휴대폰 | 폭 390 이상: **보기만**(상태 확인·알림). 입력이 많은 업무(Feature 등록·정책 편집)는 데스크톱에서 | `narrow.spec` mobile(390×844) |

Edge는 Chromium 엔진이라 chromium 시험이 대신한다(같은 렌더링·JS 엔진).

## 2. 시험 구성과 기계 시간

| 실행 | 브라우저·폭 | 이유 |
|---|---|---|
| 기본 `npm run verify`(로컬·CI) | chromium 전체 + firefox·webkit 스모크 6건씩 + chromium 768·390 스모크 7건씩 | 엔진 차이(레이아웃·폼·대화 상자·fetch 오류 처리)는 핵심 흐름에서 드러난다. 전체 시험을 세 엔진으로 돌리면 기계 시간이 세 배라 스모크만 — 추가 약 1~3분 |
| `npm run verify:full`(로컬) | 위 + 좁은 폭을 firefox(768)·webkit(390)으로 한 번 더(`e2e:engines`) | 좁은 폭 규칙은 대부분 엔진과 무관해 기본은 chromium으로 충분하고, 엔진별 차이는 출시 전 전체 점검에서 본다 |

CI(`.github/workflows/verify.yml`)는 `npx playwright install --with-deps chromium firefox webkit`로 세 엔진을 설치한다.
로컬에서 처음 돌릴 때는 `cd FF/e2e && npx playwright install firefox webkit`(처음 실행은 백신 검사로 브라우저 시작이 1분 넘게 걸릴 수 있다).

엔진 스모크(`browsers.spec`)의 6흐름: 로그인(틀린 비밀번호·로그아웃) · 대시보드(가젯·오류 없음·가로 넘침 없음) · Feature 등록(제안 폼 → 상세) ·
긴급 차단 요청(영향 범위·규칙 점검·type-to-confirm, 실제 발송 전 멈춤) · 업무 절차 흐름도(활동 상자 → 상세) · 오류 안내(5xx 문의 번호·연결 끊김).

## 3. 좁은 폭 점검 결과(2026-10-25)

| 화면 | 768 | 390 | 조치 |
|---|---|---|---|
| 셸 상단바(전 화면 공통) | **가로 넘침 227 px** — 도구 버튼 줄(약 700 px)이 화면 밖 | **가로 넘침 605 px** — 검색 칸·도구 줄·사용자 칩 | `shell/shell.css` 1024 미만: 브랜드는 로고만, 검색 칸 축소·단축키 표시 숨김, 도구 줄은 제 상자 안에서 가로 스크롤, 본문 여백 축소. 600 미만: 검색 칸 숨김 |
| 대시보드·Feature 목록·Feature 상세·긴급 차단·차량별 적용 상태 | 상단바 수정 뒤 페이지 넘침 0, 제목 화면 안, 보조 글자 11 px 이상 | 같음(표는 본문 상자 안에서 가로 스크롤) | — |
| 메뉴 | 레일 그룹 버튼 → 메뉴 덮개 패널(기존 1280 미만 동작)로 이동 가능 | 같음 | — |
| 업무 절차 흐름도 `/procedures/FPW.1` | 페이지 넘침 없음, 흐름도는 `.pf-scroll` 안에서 가로 스크롤(1960/636 px) | 페이지 넘침 없음, 흐름도는 가로 스크롤(1960/266 px — 한 번에 약 14%만 보인다) | **기록만** — 흐름도 화면은 다른 작업이 다시 꾸미는 중이라 CSS를 고치지 않았다. 390에서는 텍스트 보기(표)가 더 읽기 쉽다 |

글자 하한은 데스크톱과 같은 디자인 규칙(보조 글자 11 px, `layout-quality.spec` ④)이다 — 좁은 폭에서 더 줄지 않는다.

## 4. 남은 한계

- 휴대폰 폭은 보기만 지원한다. 입력 화면(제안 폼·정책 편집·대시보드 편집)은 390에서 쓸 수는 있으나 시험하지 않는다.
- 3D 장면·지도(MapLibre) 화면은 좁은 폭 시험 대상이 아니다(데스크톱 전용).
- WebKit 시험은 Playwright WebKit(Windows·Linux 빌드)이며 실제 macOS·iOS Safari와 세부 동작이 다를 수 있다.
