# 업무 레퍼런스 모델 요구사항

사용자 요구는 현재 업무 내용을 BASE로 모든 부서의 업무를 목적·성과·BP가 있는 하나의 레퍼런스 모델로 상세 정의하는 것이다. 지정 ASPICE 4.0 PDF의 표현 구조를 벤치마크하되 우리 업무 정의를 새로 작성한다. 원문 표준의 복제·번역·공식 적합성 평가를 산출물로 삼지 않는다.

| ID | 요구 | 수용 기준 |
| --- | --- | --- |
| WREF-01 | 현재 내용 보존 | 기존 FPW.1~14, 97활동 ID, 기존 WP·역할·RACI·Gate 규칙을 추적할 수 있고 실행 이력의 키를 재발급하지 않는다. 명확한 기존 표현 보정은 변경 근거를 기록한다. |
| WREF-02 | 하나의 원천 모델 | YAML→정상 생성기→JSON→contracts/backend 생성 모듈→지연 로딩 UI로 이어진다. 화면 전용 중복 업무 카탈로그나 생성물 손수정을 두지 않는다. |
| WREF-03 | 프로세스 시트 | 모든 프로세스에 ID·한/영 이름·목적·업무 범위·성과·진입/완료 기준·담당·연계가 존재한다. |
| WREF-04 | 원문 BP 정의 | 모든 기존 활동은 하나 이상의 안정적인 BP에 연결한다. BP는 번호·이름·수행 정의·참고·연결 활동·성과·근거 산출물을 가진다. 버튼 이름을 BP 정의로 복제하지 않는다. |
| WREF-05 | 성과 추적 | BP×성과와 산출물×성과의 두 표를 제공한다. 매핑은 정의된 성과/산출물만 가리키고, 성과에 BP와 출력 근거가 없으면 검증에서 검출한다. 링크 존재와 실제 달성/승인 판정을 구분한다. |
| WREF-06 | 14부서 전체 관점 | 부서별 목적·담당 역할·수행/책임/협의/통보·담당 BP·입출력 인계를 조회한다. 현재 빈 원가4역할·시스템관리 역할을 실제 업무 정의로 보강한다. 실제 고객사 조직 확정으로 오인시키지 않는다. |
| WREF-07 | 업무 공백 보강 | 개발비/원가기준, 접근·운영·복구, 기준정보/공유자산/연계 품질, 데이터 분석/상품 개선을 지원 프로세스로 정의한다. 정책 되돌리기는 긴급 차단 해제와 구분해 요청·독립 승인·실행·차량 수렴을 정의한다. |
| WREF-08 | 화면/권한과의 일관성 | 104화면을 업무 연결 또는 설명된 보조/조회 화면으로 분류한다. 활동의 action은 실제 경로와 허용 역할에 맞아야 한다. 플랫폼 밖 업무는 외부 수행으로 표현하며 새 가짜 API·승인·권한을 만들지 않는다. |
| WREF-09 | 현재 흐름 보존 | 기존 내 업무/담당자/전체 지도/활동·WP 상세 및 기존 `?a=`, 역할 강조, 진행 기록을 보존한다. 레퍼런스 조회가 사람의 역할이나 업무 완료 상태를 바꾸지 않는다. |
| WREF-10 | 독립적인 판정 | 업무 정의 상태, 개인의 진행 표시, Gate의 서명 판정, 공식 ASPICE 능력수준을 각각 구분한다. 기존 안전·서명·직무 분리 기준은 변경하지 않는다. |
| WREF-11 | 읽기 쉬운 화면 | 1366/390에서 목적→성과→BP→산출물·연계 순서가 읽히고, 행렬은 표 자체에서 스크롤하며 본문은 넘치지 않는다. 선택·필터가 키보드/직접 URL에서 동작한다. |
| WREF-12 | 원격 실행과 예산 | 모델과 조회 UI는 게시 산출물에 포함하고 사용자 PC의 PDF/파일 경로·개발 서버를 요구하지 않는다. 초기 297KiB와 기존 기타 예산을 유지한다. |

검증은 잘못된 BP/성과/WP/활동 참조, 커버리지 공백, 권한 불일치를 실제로 거부하는 모델 시험과, 부서 조회→프로세스 시트→BP→입출력/성과 추적 및 기존 활동 링크/진행 상태 불변을 확인하는 UI 회귀로 구성한다. 단순 개수/문자열 복제만으로 업무 적정성 완료를 판정하지 않는다.
