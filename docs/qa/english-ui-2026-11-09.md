# English UI rollout

The language button now has a reactive UI-copy lookup rather than changing navigation language alone. This checkpoint is partial: **5,114 of 8,913 Korean copy leaves have English entries** across 80 source modules, including the integrated P13 supplier source. The complete list of missing paths is [english-copy-coverage.json](english-copy-coverage.json); source expressions and hashes are in [english-copy-inventory.json](english-copy-inventory.json). Later root taxonomy/fleet additions require another inventory pass after integration. Neither source coverage nor a language-button state is a claim of full English support.

`localizedCopy` wraps only declared UI copy objects and arrays. English overrides use the exact source export/property path, and functions retain their arguments. There is no global string replacement, DOM translation or translation of server records. User names, written drafts, IDs, enum values, permissions, canonical work-product keys and approval decisions remain unchanged. Untranslated copy falls back to the Korean source and its accessed path is recorded. An unsuccessful lazy load keeps the current language and can be retried; an older request cannot overwrite a newer selection.

English catalogues load only when requested, and only catalogues containing actual translations are in the loader. The existing AppShell language subscribers receive a copy revision, so API screens and permissions consumers rerender without remounting forms or changing query keys. Stored English preference is applied after loading. Loading and failure messages are visible. Static module-level labels and views without a language subscription still need individual render review.

Static route captions, department selectors and demo/SSO role captions now use declared English display metadata. Route paths, RACI, account names, role values and the permission parser remain unchanged. Registration copy and guides, department workspace copy, workflow screen copy, six ADS copy modules, P10 and experiment-analysis copy have English entries. PRD outlines added after a language change use the active language, while an existing outline or draft is preserved. A heading-only outline remains invalid after switching language. Precise and compact quantities, KST timestamps, remaining-time units and cost captions respect the UI language; amount arithmetic, FX conversion and backend UTC values are unchanged.

The inventory follows local constants and shorthand properties, including seven ADS change-path captions and an incident-date formatter that were previously omitted. It counts already localized child exports once. `node tools/ui-locale.ts --scaffold --check` rejects unknown or duplicate translation keys and incompatible function parameters. The current catalogue has none of these errors. This validates copy contracts, not business approval or completeness of dynamic metadata.

The third checkpoint adds common empty/error/permission states, registry, Feature detail, audit, IAM and planning guidance. Display formatting in 24 screen/design files now uses the selected locale, with date/time options and numeric values preserved. Cached overview date formatters are keyed by locale. Relative-time calculations and thresholds remain identical; only minute/hour/day captions change.

The fourth checkpoint completes all **1,389 shared `ko` entries**, the ALM/external/GitLab/OTA batch (**145 required leaves**) and the Flag-code/Data-Lake/Feature-DB batch (**1,058 required leaves**, plus an existing English caption). Reconciliation-kind and evaluation-source names are explicit display objects with unchanged canonical keys. ALM function aliases defer child-copy reads until called. Workflow loading messages and inherited inbox queue captions use late getters, preserving queue keys. Of the 18 indirect references now recorded in the inventory, 15 are late getters, two forward already localized objects and one is the retained legacy PRD template; current PRD editing uses the reactive template function.

`node tools/ui-locale-types.ts` checks real source and translation primitive/structured return shapes in addition to the existing exact-argument checks: **5,174 entries checked, zero incompatible shapes**. This validates copy interfaces; it does not prove semantic equivalence or domain authorization. A production observation found Korean contract coverage labels outside the copy catalogue; nine bilingual display captions now cover the five Flag-code screen consumers. The raw status codes, severity and release-block logic are unchanged. The conservative [contract-label review inventory](english-contract-label-review.json) lists 35 other import sites requiring display review; some already use translated helpers, so this is not a confirmed-defect count.

Dynamic workflows now cache the raw source separately from their reactive display view. All 124 activity names, existing English process/work-product/role/department names, and the complete FPW.18 guidance and work-product field captions follow English selection. Untranslated descriptions remain Korean and are recorded. The separate [workflow metadata ledger](english-workflow-coverage.json) inventories **1,782 fields: 170 translated, 362 with source English, 1,250 missing**. `node tools/ui-workflow-locale.ts` validates its metadata keys and records exact source hashes. Canonical source IDs, RACI, platform guards, route mappings, layout coordinates, activity topology and work-product content array ordering are unchanged. Administrative role options still come exclusively from the allowed identity response; only their captions use the display model.

To retain the initial bundle limit, master-data and P11 domain copy no longer hangs off the global `ko` object. Its consumers import the same domain objects in their own screen modules. The Feature-summary event listener stays available immediately, while its read-only body, API queries and domain copy load when opened. Copy-factory calls are pure when unused: their only creation side effect is an internal cache. No budget, permission or test-skip limit was raised.
