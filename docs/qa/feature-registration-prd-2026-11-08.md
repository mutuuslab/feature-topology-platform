# Feature 문서형 초안

## 2026-11-09 기준 Feature DB 선행 적용

사용자 최신 요구에 따라 Feature DB 기준 행 1개를 선택하고 적용해야 이름·설명·담당·적용 대상 작성 및 등록 전 확인을 연다. 첫 화면에는 기준 선택 안내, 기준 행 추가 요청, Feature DB의 기존 기준·변경 요청 경로를 제공한다. 선택 Drawer를 적용하지 않고 닫으면 폼이 열리지 않는다. 기존 기준을 적용한 후에는 수동으로 고친 제목·본문·ASIL·담당·적용 범위를 기준 변경 취소나 적용으로 덮지 않는다. 작성 전 2000자를 입력하던 과거 시험은 기준 적용 후 작성→변경 취소·적용→동일 원문 저장 회귀로 바꿨다. 서버의 PRIMARY1개 필수 및 기존 승인·중복·폐기·범위·2000자 조건은 유지한다.

자동 채움은 실제 기존 `autofillFromRef`의 출처와 적용 후보를 사용한다. 담당은 기존 기준 정보에 값이 있으면 추천하고, 없으면 현재 계정을 준비한다. 사용자가 고친 담당·적용 대상은 늦게 도착한 자동 채움이 덮지 않는다. 작성 가이드는 가져오는 정보와 사람이 근거를 확인할 항목을 구분한다.

등록 성공 또는 서버 안내 확인 뒤에는 새 Feature ID와 Version의 `?tab=ext`로 이동해 기존 정본 JIRA·codeBeamer 연계 화면을 연다. Feature DB refId·Feature ID/Version·외부 항목 ID를 구분해 설명하고, 실패·충돌은 기존 `/integration/connectors?tab=sync`에서 권한을 가진 담당자가 재처리하도록 연결한다. 새 ALM 원장이나 등록 전 외부 항목 수동 생성은 추가하지 않는다. root 통합 ALM의 기존 Epic 자동 생성·역방향 JIRA Feature 생성·산출물 갱신·동기화 가드를 그대로 사용한다. 실제 회사 외부 계정이 제공되지 않아 소프트웨어 회귀·정적 시연과 실연동 완료를 구분한다.

production 정적 시연에서 새 ID는 빌드 시점 스냅샷이 없어 연계 탭이 오류로 끝나는 것을 관측했다. 기존 ext-mock reader에 새 브라우저 초안 조회만 보강했다. 저장된 mock 연결과 실제 관측된 codeBeamer 요구만 표시하고, 없으면 Epic 없음·미확보 요구로 표시한다. Epic·외부 승인·실연동 성공을 합성하지 않으며, 기존 스냅샷과 알 수 없는 Feature의 조회는 기존 처리에 맡긴다. 별도 회귀3개가 이 경계와 정확한 Version 연결을 확인한다.

이번 영향 실행은 frontend6파일70PASS, 새 정적trace+등록2파일35PASS(등록32개 중복), backend기준DB·PLE·정책60PASS와 실제HTTP/DB PRD2PASS다. 타입·copy·tokens·spacing·docs-meta·시험위생 정책을 통과했다. 최종3폭 production 재관측과 root 통합본 전체시험은 별도 증거로 확인한다.

아래는 이전 문서형 초안의 이력이다. 첫 화면 직접 작성 및 최초 기준 선택 전 입력 허용은 최신 요구로 대체되었다. 최신 구현의 검사 결과와 고정 아티팩트는 통합 인계 기록에 별도로 연결한다.

## 2026-11-08 문서형 초안 이력

사용자 지시: Feature 등록 UI/UX에 Jira PRD 스타일을 적용한다. [Atlassian 공식 Product requirements 템플릿](https://www.atlassian.com/software/confluence/templates/product-requirements)의 목적·가정·사용자 동작·지원 자료·범위 분리를 참고했다. 저장 계약에 맞춰 문서 본문과 기존 속성을 구분했으며, 이름만 비슷한 외부 연동이나 저장되지 않는 속성을 만들지 않았다.

첫 화면에서 이름과 설명을 직접 작성한다. 제목 옆의 ‘미등록 초안’은 아직 저장하지 않았다는 뜻이다. 설명에는 선택적으로 `[배경과 문제]`, `[기대 동작]`, `[완료 조건]`, `[범위와 제약]` 목차를 추가할 수 있다. 작성 내용 뒤에 추가하며 기존 본문을 덮거나 잘라 저장하지 않는다. 편집·미리보기 모두 같은 문자열을 쓰고 미리보기는 React 텍스트로 표시한다. HTML을 실행하거나 외부 자료를 자동으로 불러오지 않는다.

본문 전체는 기존 `CreateFeatureBody.description`의2000자 계약 안에서 그대로 저장한다. 목차만 있는 문서는 실제 내용 작성을 안내한다. 별도 섹션별 저장 필드·priority·epic·외부 Jira 쓰기 기능을 추가하지 않았다. 요구사항 ID는 문서 본문과 별개의 기존 연결 칸이다.

담당·적용 국가/차종/트림·ASIL/변경 사유·요구사항/분류·기준/참고 연결은 실제 기존 속성이다. 속성 패널을 본문 옆에, 좁은 화면에서는 아래에 둔다. 상단과 하단의 등록 전 확인은 같은 검증 조건과 최종 검토를 사용한다. 범위 확인 체크 전에는 등록되지 않는다. 저장 결과는 기존 PROPOSED0.1.0이며 정의 승인·차량 배포는 뒤의 별도 절차다.

기준 선택은 보조 Drawer에서 한다. 임시 선택과 적용된 연결을 분리해 닫기/취소로 본문·소유자·기본값·연결이 변하지 않게 했다. 적용 때만 기본값과 PRIMARY1개/INCLUDED 연결을 함께 반영한다. 최초 기준 선택 전 직접 쓴 이름·설명·태그도 보존하고, 직접 고른 ASIL은 기존 변경 사유 규칙을 유지한다. 빈 칸 또는 아직 고치지 않은 이전 기준값만 바꾼다. 추가 요청 Drawer는 선택 Drawer와 번갈아 열며, 기존 확인 창의 최상단 키보드 처리를 보존한다.

기존 SUIT/JetBrains·의미 색상·Button/Field/Drawer/RefStatusBadge를 사용한다. 데스크톱은 문서+속성 열,1000px 이하에서는 단일 열이다. 속성 높이는 내용에 맞추고 문서가 길어도 상단에서 검토를 열 수 있게 했다. 최종 검토와 Feature 상세에서도 설명의 줄바꿈을 보존하며 빈 설명의 기존 누락 표시를 유지한다.

Figma 후보는 파일 `CFFGwN4rHvDCq5IYa7sVCt`, 별도 페이지 `91:2`, 데스크톱 `91:7`, 모바일 `91:850`, Rationale `93:2 / DR15`다. 이전 등록v2 화면과 모바일7f1344f1 체크포인트를 보존한다. Figma 수정은 별도 담당자가 실제 구현·검증 상태에 맞춰 관리한다.

실제 검증:

- frontend3파일48개 통과. 직접 작성한2000자·제목·ASIL→최초 기준 선택→동일 본문과 두 역할 POST, 취소 입력/연결 보존, 기존 권한·범위 검토·서버 거절·초점, 목차 추가와 안전한 텍스트 미리보기를 포함한다. 새로운5개와 기존 등록24개, 모바일6개, 정책13개다.
- backend `feature-prd.spec.ts`2개 통과. 실제 HTTP/DB에서2000자 다중행 POST→PROPOSED0.1.0→상세GET 원문·담당·PRIMARY1개를 확인했다.2001자는400이며 잘라 저장하거나 저장되는 척하지 않는다.
- frontend 타입·문구·토큰·간격·시험 위생5게이트, 문서 메타·deadcode·OpenAPI·요구사항·ADS team5게이트를 통과했다. 최종 `9484-prd3`은297.0/297KiB·화면묶음32.7/40KiB·로컬 흔적0이다. 이전 산출물은 보존했다.

실제 CSP 미리보기에서 선택 뒤 닫힐 때 초점이 사라지는 결함을 확인하고 독립회귀를 RED로 재현했다. 부모의 닫기callback이 매번 바뀌어 Drawer의 초점 기억 effect가 초기화되는 원인이었다. 이 화면의 닫기callback만 안정화하고48개를 다시 통과했다. 추가 요청 취소→선택 창 닫기도 원래 버튼으로 돌아오는지 검증한다. 공통 Overlay와 API는 변경하지 않았다.390px 시각 검토 후 초기 편집기를8줄로 조정하고 목차 추가·글자수를 본문 위에 두었다.

최종 `9484-prd3/packed`는30,348개 원본 파일에서 VIN별 묶음으로17,869개 물리 파일을 사용한다(한도20,000).12,960개 논리 GET·HEAD의 본문과 나머지17,388개 파일의 바이트가 원본과 동일함을 전수 확인했다. snapshot coverage 틈0이며 데이터나 허용치를 줄이지 않았다.

실제 배포 CSP·인증 게이트·원래 URL resolver를 쓰는 별도 미리보기 `http://localhost:9486/`에서390/768/1366px의 등록·정책·차량·절차12뷰를 통과했다(JS·실패 요청·외부 요청·HTTP오류0). 별도3폭 PRD 여정도 직접2000자 작성→안전한 미리보기→기준/참고 임시 선택 취소·적용→검토 범위 확인→시연 저장→상세 원문2000자와 줄바꿈 보존을 확인했다. 선택/적용 후 원래 버튼으로 초점이 복귀하며 임의 HTML은 실행되지 않는다.1366px·390px 실제 이미지를 검토했다.

PRD의 새 항목은 빌드 시점에 없으므로 기존 시연 reader가7개 snapshot을404로 탐색한 뒤 브라우저 overlay를 반환한다.3폭 합계21개 탐색404와 본문 미소비로 인한 동일 요청의 ERR_ABORTED는 근거에 그대로 기록했다. 성공적으로 저장·표시된 ID의 정확7경로만 구분하며 나머지 HTTP오류·요청 실패·JS오류·외부 요청·예기치 않은 대화상자는0이다. 이를 전 네트워크 오류0으로 표현하지 않는다. 별도 실제 서버 HTTP/DB2개 시험과 브라우저 시연 저장은 서로 다른 근거다.

공개 원격 CI·Cloudflare 게시·다른 후속 묶음 통합은 이 문서의 로컬 통과 범위가 아니다. 허용치·래칫·건너뛰기를 변경하지 않는다.
