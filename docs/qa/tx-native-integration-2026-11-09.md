# 분류·지역·브랜드 기능 통합 체크포인트

TX 원천 `gap/tx@5cc12c69`의 5개 커밋을 현재 등록 자동화·P10·P13·대시보드·업무 실행·영어 구조와 통합한다.

- L0~L5 노드 등록/명칭·설명 수정/삭제, Feature 배치와 경로, 지역 코드 후보 조회, 브랜드·지역·법규 룰 조건의 정책 조회·등록·수정을 제공한다.
- 발행된 Feature DB 분류는 직접 바꾸지 않는다. 상위는 정확히 한 단계 위여야 하며 삭제 ID 재사용, 하위/배치가 있는 노드 삭제, 다른 수준 배치를 거부한다.
- 브랜드 조건은 별도 메타데이터다. 이 연결 자체를 정책 승인·실차 배포·안전 판정으로 취급하지 않는다. 수정은 사람 역할만 요청하고 서비스가 실제 Feature Owner 또는 시스템 관리자인지 다시 확인한다.
- 현재 등록의 빈 차량 범위 기본값·Feature DB 우선 선택·자동 채움·입력 보존·Drawer·PRD 제한 및 P10/P13/서명 가드를 보존했다.
- 기존 첫 화면 예산 **297KiB**를 유지한다. 원천 분기의 298KiB 상향은 수용하지 않았다.
- 요구 판정 `review.json/status.json/REPORT.md`는 기존 원장을 유지한다. 코드 통합만으로 원천 분기의 26개 완료 판정을 복사하지 않았다.

## 실제 검증

- contracts 4파일 **74 PASS**(숫자 검증40 포함).
- backend 4파일 **38 PASS**: 분류/지역/브랜드, 사람·기계 및 실제 Owner/비소유자/관리자 경계, P10 출시, P13 검수.
- frontend 3파일 **42 PASS**: 분류 화면, Feature DB 우선 등록, 등록 추적. 통합 FE/BE 타입 PASS.
- migration 잠금 **90개**, 신규261 하나만 추가하고 기존89 SQL 해시는 불변.
- 실제 격리 API9546에서 **24역할/210권한/16직무분리/108화면/13계정**, 계약 dist와 차이0.
- 업무 모델 오류0/경고0, IAM 신선도 차이0, 문서59개·JSON·HTML 생성, pytest7 PASS. 분류 관리는 `FPW.14-A06`/`WP-PLATFORM-TAXONOMY`로 연결하고 Feature 배치는 `FPW.1-A01`, 브랜드 조건은 `FPW.4-A03`에 연결했다. 원래 활동 ID를 보존하며 18절차/125활동/124산출물이다.

출시 후보 양성 시험이 422로 막힌 원인은 실제 G6 협력사 근거 누락이었다. 합성 시험용임을 표시한 10개 본문을 native 서비스에서 검증·분리 검수하는 선행조건을 갖춘 뒤 통과했다. G6 검사를 완화하지 않았다.

## 후속

- 원천 TX 화면은 정적 모드에서 관리/배치/조건 수정을 숨기고 스냅샷도 main에 연결되지 않았다. 브라우저 시연의 실제 쓰기·권한·감사·삭제 묘비와 조회 정합을 추가해야 하므로 게시 기능 완료로 보고하지 않는다.
- 새 분류·지역·브랜드·협력사 화면의 영어 표시 및 외부 계약 label을 현재 KO/EN 구조에 맞춘다.
- 시장 대응 표의 OTHER 묶음과 Variant Rule 대응 정의는 원천 문서의 '확인 필요' 경계를 유지한다. 회사 원본이나 실차 판정을 임의로 생성하지 않는다.
- 새 운영 빌드 성능·실제 브라우저·정적/실API E2E는 후속 구현과 함께 다시 검증한다. 기존 source9fe의38/38 결과를 이 변경 전체의 E2E 근거로 사용하지 않는다.
